# UDP 视频传输上位机 · 对接说明（Vitis `udp_camera` 工程）

本目录是 PC 端接收程序，用来接收 `D:\FPGA\Vitis\UDP\prj\udp_camera` 这块 Zynq 板子发出来的 OV5640 JPEG 视频流。

## 1. 板子端实际发的是什么（从源码读出的事实）

| 项目 | 值 | 出处 |
|---|---|---|
| 板子 IP / 掩码 / 网关 | `192.168.1.10` / `255.255.255.0` / `192.168.1.1` | `main.c:51-53` |
| 目标（PC）IP | `192.168.1.102` | `udp_perf_server.h:28-33` |
| 目标端口 / 本地端口 | `5002`（原为 5001，已按 §4 改） | `udp_perf_server.h:35-36` |
| 每包负载 | `1024` 字节，**无任何包头** | `udp_perf_server.h:40-42`、`main.c:118` |
| 数据内容 | OV5640 硬件 JPEG 字节流（`FF D8` 开头、`FF D9` 结尾，帧长可变） | 开发记录 §1、§4.6 |
| 分帧方式 | 包边界与帧边界无关，需 PC 端按 `FFD8/FFD9` 拼帧 | 开发记录 §6 |

所以上位机必须用 **`JPEG 裸流(FFD8/FFD9 拼帧)`** 模式；其它三种（分片带头 / 单包 / RAW）都不匹配。

## 2. 上位机设置（接收 RX 页）

| 控件 | 应填 | 说明 |
|---|---|---|
| 协议类型 | `JPEG 裸流(FFD8/FFD9 拼帧)` | 对应板子 1024 字节无头裸流 |
| 本地地址 | `192.168.1.102`（下拉里选网卡 IP） | 板子只会往这个地址发，网卡必须先配成这个 IP |
| 本地端口 | `5002` | 板子已改为发往 5002（原 5001 被 NI 服务占用） |
| 远程地址 | `192.168.1.10` | 只接受板子发的包，防止串流 |
| 远程端口 | `5002` | 板子的源端口（`UDP_LOCAL_PORT`） |
| 接收缓冲 | `4096` KB | 100M 网口够用；丢包多就加到 8192 |
| RAW 参数 | 不用管 | 只有选“原始 RAW”模式才用 |

发送 TX 页用于反向往板子发（板子当前只收不发，一般不用）。

## 3. 板子侧已修改的一处 bug（原来不改就永远解不出图）

`main.c:58` 原为 `MAX_PKT_LEN = 1031`，`main.c:113` 用它启动 DMA，即 DMA 一次从 FIFO
搬走 **1031** 字节；但 `main.c:118` 只把 **1024** 字节发出去。多搬的 7 字节已被 FIFO 消费，
既没发出去也回不去 —— 接收到的字节流每 1031 字节有 7 字节空洞，JPEG 数据被撕碎，
PC 端再正确的拼帧也解不出图（表现：包数/码率在涨，但“已收帧”始终 0、“解码失败”猛涨）。

**已改为：**

```c
/* main.c:58 */
#define MAX_PKT_LEN     1024      /* 与 UDP_VIDEO_PKT_LEN 保持一致 */
```

## 4. 端口 5001 冲突（已绕开）

本机 `Get-NetUDPEndpoint` 显示：

```
0.0.0.0:5000 -> nidmsrv
0.0.0.0:5001 -> lktsrv      ← NI(LabVIEW) 服务占着，普通程序绑不上（10013/10048）
```

**已把板子的 `UDP_DEST_PORT` / `UDP_LOCAL_PORT` 改成 `5002`**，上位机默认端口也改成 5002，
两边一致即可，不需要动 NI 服务。

如果以后要换端口：板子改 `udp_perf_server.h:35-36`，上位机“本地端口/远程端口”同步改，重启板子和接收。

## 5. PC 网卡配置（板子写死了目标 IP）

板子固定发往 `192.168.1.102`，所以 PC 有线网卡要配成静态地址：

```
IP    : 192.168.1.102
掩码  : 255.255.255.0
网关  : 可留空（直连时不需要）
```

用网线直连板子（或经过同一台交换机）；本机当前网卡列表里没有 192.168.1.x，
必须先新增这个地址，否则包根本到不了本机（可在“网络参数”里看到本机 IP 列表确认）。

Windows 防火墙首次运行会弹窗，选“允许访问”；如果没弹，就手动给 UDP 5001/5002 放行入站。

## 6. 使用步骤

1. 按 §5 配好 PC 网卡，网线接板子；
2. （若还没改）按 §3 修 `MAX_PKT_LEN`、按 §4 定端口，重新编译下载板子；
3. 板子串口会打印 `Target IP : 192.168.1.102 (port 5002), 1024 bytes/datagram`，
   先确认它和你要填的一致；
4. 双击 `启动上位机.bat`；
5. 接收页：协议类型选 `JPEG 裸流(FFD8/FFD9 拼帧)` → 本地地址选 `192.168.1.102`
   → 本地端口填对应端口 → 远程地址 `192.168.1.10`、远程端口同板子源端口 → 点“开始接收”；
6. 正常表现：`已收帧` 递增、`帧率` 约等于 OV5640 帧率（640×480 JPEG 一般十几到三十帧）、
   `解码失败` 保持 0；画面实时刷新。
7. 录像存 `recordings\`，截图存 `captures\`。

## 7. 自检（不需要板子也能验证程序本身）

```
python udp_video_station.py --selftest
```

会依次跑：分片环回、RAW 环回、单包环回、自动识别（单包/分片）、远程地址过滤、
JPEG 裸流（1024 字节/包、无包头），全部 PASS 说明程序侧链路没问题，剩下的就是网络/板子侧。

## 8. 常见现象对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 点“开始接收”弹端口占用 | 5001/5000 被 NI 服务占用 | 换端口（§4） |
| 有包数、码率，但“已收帧”一直是 0、解码失败猛涨 | DMA 1031 / UDP 1024 不一致，流被撕碎 | §3 |
| 完全没包 | PC 网卡不是 192.168.1.102、网线/交换机不通、防火墙拦截 | §5、抓包确认 |
| 偶尔花屏、解码失败间歇上升 | UDP 丢包（100M 网口 + 大帧） | 降低 JPEG 质量或加 4 字节包序号 |
| 帧率很低（1~3 fps） | 100M 网口 + 640×480 JPEG 大帧带宽不够 | 降分辨率/质量，或改千兆口 |
